# ParCool 3.4.x × Stamina [DLTB] Bridge (Forge 1.20.1)

ParCool перестає мати власну шкалу витривалості: усі його дії (біг, вальт, стрибки зі стін, перекати тощо)
беруть і витрачають витривалість зі шкали **Stamina [DLTB]**. Шкалу ParCool на екрані міст ховає.
Налаштування ParCool міняти не потрібно.

Для ParCool **3.4.x** (перевірено за кодом 3.4.3.0). Для ParCool 4.x потрібна інша збірка моста.

## Встановлення

На клієнті **і** на сервері (якщо граєте на сервері) у папці `mods`:

- Forge 1.20.1 (47.4.x)
- Kotlin for Forge
- ParCool 3.4.x
- Stamina [DLTB]
- цей міст (`parcool-dltb-bridge-1.0.0.jar`)

## Налаштування

`config/parcooldltb-common.toml`:

- `cost_scale` (за замовчуванням `0.5`). ParCool за замовчуванням має шкалу 2000, а DLTB 1000, тому множник 0.5
  зберігає пропорції витрат. Збільшіть, щоб паркур сильніше втомлював, зменшіть, щоб він був дешевшим.

### Подвійне списання при бігу

DLTB сам списує витривалість за спринт, а дія ParCool `Fast Run` теж має вартість. Якщо біг витрачає забагато,
у налаштуваннях ParCool (Alt+P → вартість дій) поставте для Fast Run витрату 0.

## Як це працює

- Міст на клієнті навішує на локального гравця свою реалізацію capability витривалості ParCool
  раніше за ParCool (пріоритет HIGHEST), тож ParCool працює з нею, не знаючи про підміну.
- Читання: клієнтська копія шкали DLTB (значення і виснаження), перерахована в одиниці ParCool.
- Витрата: ParCool рахує вартість на клієнті, міст збирає її за тік і одним пакетом шле на сервер, де вона
  списується через публічний `StaminaAPI` DLTB. Сервер лишається єдиним джерелом правди.
- Відновлення і виснаження: повністю на боці DLTB.
